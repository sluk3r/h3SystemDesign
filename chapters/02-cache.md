## 2.1 为什么说缓存是“银弹也是手榴弹”

> **写作提示**：缓存的哲学——用空间换时间，用不一致换性能。问题不在于“用不用缓存”，在于“你准备付出什么代价”。

- [ ] 用空间换时间
- [ ] 用不一致换性能
- [ ] 代价清单

## 2.2 演化：从单机 HashMap 到 Redis Cluster

> **写作提示**：单体架构时 `new HashMap()` 就够了；分布式后缓存一致性立刻变成噩梦。为什么 Redis 取代了 Memcached——数据结构 > 性能差异。

- [ ] 单机时代：HashMap 的快乐
- [ ] 分布式后：一致性的噩梦
- [ ] Redis vs Memcached：数据结构决定了生态位

## 2.3 缓存穿透：布隆过滤器的数学直觉

> **写作提示**：不存在的数据反复查询 → 缓存形同虚设。布隆过滤器的直觉——“一个绝对不会漏判、但可能误判的黑名单”。用“彩色球扔进桶”的类比替代公式。

- [ ] 事故重现：恶意查询不存在的 ID
- [ ] 布隆过滤器的几何直觉
- [ ] 误判率的工程意义

## 2.4 缓存击穿：热点数据过期的瞬间

> **写作提示**：一个 key 过期 → 十万请求同时涌入数据库。互斥锁方案简单粗暴但有效。“永不过期”+ 异步更新是另一种哲学。

- [ ] 事故重现：热搜商品过期
- [ ] 互斥锁方案
- [ ] “永不过期”+ 异步更新

## 2.6 缓存一致性：十年争论

> **写作提示**：“先删缓存再更新 DB” vs “先更新 DB 再删缓存”。为什么最终都是“延迟双删”或者“订阅 binlog”。Canal 的原理——假装自己是一个 MySQL 从库。

- [ ] 先删缓存再更新 DB
- [ ] 先更新 DB 再删缓存
